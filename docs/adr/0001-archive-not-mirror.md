# Архив, а не зеркало Telegram

Message записывается один раз и после этого не меняется: ни удаления, ни правки в Telegram не отражаются в БД. Telegram не даёт надёжного способа узнать полный список удалённых id, а правку нельзя обнаружить инкрементальным проходом по `tg_msg_id` — она не меняет id и не поднимает сообщение вверх по `iter_messages`. Мы сознательно делаем снимок-на-момент-выгрузки, а не живое зеркало: это упрощает ingest и делает поведение архива предсказуемым.

## Considered Options

- Сверка окна N последних сообщений при каждом pull: дала бы частичный hard delete и подхват правок свежих постов, но не покрывает старые изменения и удваивает трафик каждого цикла ради неполной гарантии.
- Подписка на события удаления и правок через MTProto updates: требует daemon-режима, что противоречит выбору периодического запуска по расписанию.

## Consequences

- `edit_date` записывается как есть при первичной выгрузке: он говорит, что пост правили до момента выгрузки, но не гарантирует, что текст в БД — последняя редакция.
- Инкрементальный pull забирает только сообщения новее `newest_processed_id`. Никаких перезаписей существующих строк он не делает.
- Метрики (`views`, `reactions`) по той же причине фиксируются навсегда на момент выгрузки — см. ADR-0002.
