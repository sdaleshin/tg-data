# tg-data

Личный текстовый архив Telegram: выгрузка сообщений из whitelist-источников в Postgres через Telethon.

## Language

**Source**:
Любой индексируемый Telegram-чат: канал, чат комментариев или обычная группа. Единица whitelist — один Source. Source может быть только тот чат, в котором личный аккаунт уже состоит: вступление выполняется вручную в Telegram и частью tg-data не является.
_Avoid_: channel (слишком узко), chat, peer.

**CommentChat**:
Source с `kind=comment_chat` — linked discussion group канала, куда попадают комментарии под постами. Отдельной таблицы нет; отличается наличием `linked_channel_id`. Единственный вид Source, который читается без членства в нём (ADR-0004).
_Avoid_: discussion group, подканал.

**ThreadRoot**:
Автоматическая копия поста канала, появляющаяся в CommentChat: вокруг неё группируются комментарии к этому посту. Единственный мост между комментарием и постом канала.
_Avoid_: корневое сообщение, автофорвард, service message.

**Message**:
Одна строка в БД — сырая единица текстового контента из Telegram: пост канала, комментарий или сообщение в группе. Сохраняем только если есть `text` или `caption`.
_Avoid_: msg, запись, document, пост (неоднозначно: пост канала ≠ сообщение группы).

**Whitelist**:
Набор Source с `is_active=true`, которые ingest обрабатывает. Source включают и выключают, а не удаляют: выключенный Source сохраняет все свои Message.
_Avoid_: список источников, фид.

**Backfill**:
Первичная выгрузка истории Source от новых сообщений к старым, вглубь до границы архива. Завершается, когда `backfill_done=true`.
_Avoid_: initial sync, первоначальная загрузка.

**Граница архива**:
Дата, старше которой сообщения не выгружаются вообще. Общая для всех Source и задаёт дно, до которого доходит backfill.
_Avoid_: cutoff, глубина, since.

**Fetch**:
Процесс выгрузки данных из Telegram и записи их в Postgres. Включает backfill и инкрементальный pull.
_Avoid_: ingest, парсинг, краулинг, сбор данных.
